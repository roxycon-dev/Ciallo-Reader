# Ciallo Reader 1.4.18

1.4.17 的小说发现只扫描首页上的文字链接，于是漏掉了一批真实栏目：番茄的榜单由脚本和 JSON 提供，SF 的分类是图标链接，话本的排序入口在二级分类页，书阁用查询参数区分分类。首页没有写着「排行榜」，并不等于源站没有榜单。本轮逐源核对这些公开栏目，再接入真实数据。

| 源 | 推荐 | 章节更新 | 榜单 | 分类来源 |
| --- | --- | --- | --- | --- |
| 番茄 | 公开推荐接口 | 公开更新接口，带真实 `updateTime` | 返回可读文字的作品榜 | 榜单页 `rankCategoryTypeList`，保留男女频与原 ID |
| 话本 | 原站首页 | 分类下的 `updatetime` | 七日点击榜 / 新书（`createtime`） | 首页原生频道与题材链接 |
| SF 轻小说 | 桌面首页公开推荐 | `/lateList/` 与续页接口 | 人气 / 新书 / 畅销 / 月票 | `/category/` 图标父节点标签 |
| 爱下 | 原站首页 | `/new/` | `/hot/`、日榜、月榜 | 原生 `/sort/{id}/` |
| 书阁 | 原站首页 | `/novels` 默认更新顺序 | `/novels?sort=heat` | `cat` / `tag` 参数原值，去掉计数与描述 |
| Wenku8 Library | 公开热度等级推荐 | 全目录 `updatedAt` | 热度等级 / 上升等级 | `/api/categories`，逐书 `tags` |
| Novelia | 源站已关闭游客列表（HTTP 401） | 同左 | 公开日榜（成为小说家 / Kakuyomu） | 原前端流派选择器 |
| 全本小说网 | 真实推荐与分类 | 原站未公开，明确提示 | 原站未公开，明确提示 | 原生 `/c/{category}.html` |

Z-Library 不加入小说发现；自定义源继续执行其静态 explore / Legado 规则，没有规则就不猜路径。

Novelia 的 `/api/novel` 现在对游客返回 `401 游客没有权限执行此操作`，推荐与更新因此不可用，只有 `/api/novel/rank/*` 仍返回数据。该源按实际能力只提供榜单：选择推荐或更新时直接给出原因，不再发出必然失败的请求，也不拿日榜冒充推荐。

分类按原站原名与明确别名映射，组合题材可归入多个维度（例如「科幻末世」既是科幻也是末世）。书名和简介里的关键词不参与冒充分类；同一筛选对应多条原站路径时会逐条请求并去重，不会只取第一条。

## 顺带修掉的连接问题

文库和新轻小说都挂在 Cloudflare 后面，DNS 把 IPv6 地址排在 A 记录之前。在没有 IPv6 出口的网络里，每个请求都要先在一个不可达地址上白等一个连接超时：70 页的文库目录在模拟器上要 100 秒以上，最终整源超时失败。现在解析结果统一把 IPv4 排在前面，IPv6 保留为回退。同一台模拟器上，七个源的三栏核验从 162 秒降到 15.9 秒，文库冷启动 11.6 秒，热缓存后即时返回。

## 卡片参数排版

「自定义卡片参数」原来把标签压在滑动条的数值气泡预留区里，名称和拖动条重叠。现在名称与当前值独占一行、滑动条在下方，气泡有自己的空间，大字号下名称可以换行而不再压住数值。
