# 多语言搜索 v2：本地优先、在线补齐、用词可见

本轮专门改善搜索路径。输入中文后，原词立即搜索，本地资料先补常用词与专名；名称缺失或只有部分语言时，再从在线名称资料补齐。新名称到达就显示、加入书源队列并缓存。没有查到可靠别名时，继续使用已有关键词。

## 可以直接验收的行为

开启书源选择面板中的“多语言搜索”和“缺词时在线补充”，选择需要的书源。

1. 搜“眼镜”：搜索框下应出现原词、`glasses`、`眼鏡`。点击“搜索用词”可查看每个词的来源和已提交书源数量。
2. 搜“我的青春恋爱物语果然有问题”：捆绑词库的中文名通过已知拉丁别名连接本地 AniList 标题，能补出 `やはり俺の青春ラブコメはまちがっている。`、`My Youth Romantic Comedy Is Wrong, As I Expected`、罗马音和 `Oregairu`。这个例子已用实际捆绑数据做离线回归。
3. 搜一个本地未收录的人物 / 角色：先显示原词和“正在在线补充名称”；查到经详情验证的别名后，立即追加在搜索框下。缓存成功显示“已在线补充并缓存”。重复搜索或重启应用后，已经缓存的名字可以直接使用。
4. 临时断网或查询失败：原词和已有词仍可搜索，界面显示失败 / 超时，不会把错误当成“没有此名字”。失败采用短重试期限，不会长时间阻止再次补词。
5. 多个词用空格或逗号分开：优先生成完整英文 / 日文查询，未知部分保留原词。每轮最多 6 个完整查询，含原词，避免组合请求爆炸。
6. 输入带明确站点表达式的查询：沿用手动表达式。系统自己补出的词是普通名称，例如 `glasses`，不会强加 `female:`、`parody:` 等站点语法。

网络、提供者收录情况和重名会影响能否找到在线名称。无法确认是同一对象时不自动猜测。出现在线词也不保证第三方书源一定返回资源；结果保留书源实际返回的内容，仅同源相同资源 ID 去重。

## 搜索框下的含义

| 显示 | 含义 |
| --- | --- |
| 正在在线补充名称 | 本地资料仍不完整，正在查名称提供者 |
| 已在线补充并缓存 | 本轮在线名称产生扩展词，持久缓存写入成功 |
| 已使用缓存 | 使用此前保存的在线名称 |
| 查询失败 / 超时 | 本轮提供者请求失败或耗尽补词窗口，已有搜索保留 |
| 未找到更多可靠名称 | 本轮没有经确认的新名称，不等同于书源没有资源 |
| 原词 / 本地 / 在线 / 在线缓存 | 关键词来源 |
| 等待提交 | 词已被采用，尚未进入对应书源请求调度 |
| 已提交 N 个书源 | 已进入 N 个书源的查询调度；可能由短期搜索结果缓存响应，不能据此声称发生了 N 次网络请求 |

即使只有原词也展示这个组件。收起时显示两行关键词及状态；展开后能复制关键词、查看来源和提交数量。详情限高滚动，长书名不会占满结果列表。

## 实现与取舍

- 本地种子、完整词库、已缓存名称共同合并，种子不再提前挡住其他资料。作品的已知外文别名精确桥接本地标题，避免把外传、角色名或普通词的子串错误映射成另一部作品。
- 作品需要原文和正式英文名才视作语言完整；人物可使用原文与经过验证的罗马音。罗马音不冒充正式英语，完整性不由无关对象拼凑。
- Wikidata、Bangumi 作品 / 角色 / 人物按候选类型并行。Bangumi 先取详情验证中文名 / 别名，避免搜索列表只显示日文时漏掉中文人名。已知别名可继续连接 AniList 正式名称。
- 各提供者流式发布，整体补词窗口 12 秒；原词和本地词先搜索，不等联网结束。缺失的复合词分量并行查找，为最终完整组合预留查询位置。
- 持久缓存在应用私有 `filesDir/keyword_lookup_v2`；AtomicFile 保证原子写入，最多 512 查询。完整名称缓存 30 天，部分名称 6 小时，但是否再次请求按提供者重试状态决定。可靠旧正缓存按需迁移，旧负缓存不沿用。
- 提供者确认空结果重试 10 分钟、重名 1 小时、一般失败 60 秒、查到结果 6 小时；429 / 503 有主机冷却。响应结构异常按失败处理。可靠单实体外文名建立反向缓存，避免不同对象互相覆盖。
- 大词典更新独立后台进行，下载阶段不占本地查词锁，也不消耗当前补词窗口。普通书源查询沿用原有并发、源内串行、超时、登录错误和结果显示策略。
- 在线补词关闭、无痕或隐私模式下不发补词请求。翻译 / OCR 路径没有改变。

## 资料与来源

资料查询只读取名称和别名，没有接入生成式翻译，也没有把用户的书源账号传给名称提供者。

- [EhTagTranslation 数据库](https://github.com/EhTagTranslation/Database)：本地普通词 / 专名资料；原有捆绑资产和许可保留。
- [Bangumi 官方 OpenAPI](https://github.com/bangumi/server/blob/master/openapi/v0.yaml)：作品、角色和人物搜索及详情。
- [Wikidata 官方 API 说明](https://www.wikidata.org/wiki/Wikidata:Data_access)：名称、别名和实体查询。
- [AniList 官方 GraphQL 文档](https://docs.anilist.co/)：作品 / 角色 / 人物的正式原名和外文名。
