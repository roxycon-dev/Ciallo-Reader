# Ciallo Reader 1.3.4

版本 1.3.4 / 215，Android 7.0+，arm64-v8a。针对用户反馈的荣耀 200 Pro 漫画增强等待继续优化。

## 执行变化

- 原 V1 1200p ESRGAN 模型文件、SHA-256、输入分辨率、FP32、48 px 核心、16 px 边缘、强度混合和最终尺寸预算均保留。没有量化、FP16、换轻量模型或缩小输入。
- 每个 80×80 输入块保留全部像素。哈希命中后必须逐像素完全一致，才能复用之前的 96×96 FP32 网络核心；有一个像素变化、哈希碰撞或边缘上下文变化都会重新推理。空白块第一次也运行原模型，不以白色直接填充替代网络输出。
- 缓存存储混合强度之前的浮点结果，仍按当前强度和原图透明度合成。最多 8 块，数组载荷 1,089,536 B（约 1.04 MiB），复用淘汰条目的数组，避免持续分配。缓存在会话空闲 15 秒、退出阅读或内存压力清理时同时释放。保持单页串行、一个原生会话，极简档仍关闭增强。
- 每块从逐行约 80 次读取改为一次区域像素读取，再执行完全相同的边缘复制；强度混合直接使用已读原像素。批量写入输入、批量读取输出核心，减少缓冲逐元素访问。
- 新增 CPU_BALANCED 候选：最多 5 线程，ORT 动态任务粒度 `session.dynamic_block_base=4`。按设备与系统版本重新比较原 4 线程 CPU、动态 CPU、XNNPACK 和 NNAPI；候选须至少快 15%，最大浮点误差 ≤0.0015、平均误差 ≤0.0001，才能保存并采用。并非按品牌强制指定 GPU，也不假定驱动支持整个模型。创建与计算失败会退回原优化 CPU。
- 日志增加实际推理块数和精确复用块数。更新目录增加简短的 1.3.4 条目，沿用现有弹窗与动效。

荣耀官方参数显示 [200 Pro 使用第三代骁龙 8s](https://www.honor.com/cn/phones/honor-200-pro/spec/)。大小核调度候选依据 [ORT 动态任务调度说明](https://onnxruntime.ai/docs/performance/tune-performance/troubleshooting.html)；线程数量和加速方案由设备测量选择。桌面随机输入块对原 4 线程与 5 线程动态方案运行真实模型，两者 FP32 输出误差为 0；桌面动态方案较慢，会被择优规则拒绝。未连接荣耀手机，不能证明此候选在该机更快。

## 真实模型桌面验证

同一桌面 CPU / 4 线程 / 原始模型，Python ONNX Runtime 1.29.0（APK 使用 Android 1.28.0），两个 300×450 合成样图，每页 70 块。每次使用新会话和空缓存，含创建、全部输入组织、推理与拼接，不含 PNG 写盘，不含 Android 首次后端探测；逐次结果保存在本地 benchmark.json。仅比较精确图块复用，不把合成图当成《别当欧尼酱了》实页，也不外推手机成绩。

| 样图 | 1.3.3 路径 | 1.3.4 精确复用 | 实际推理 / 复用 | 输出最大 / 平均误差 |
| --- | ---: | ---: | --- | --- |
| 大面积留白 | 10.05 s | 2.12 s | 13 / 57 | 0 / 0 |
| 密集线条 | 10.02 s | 9.86 s | 70 / 0 | 0 / 0 |

留白样图约快 4.7 倍；无重复块的密集页收益有限。所有 FP32 输出逐项完全一致。图块复用收益取决于原像素：压缩噪声或不同底色会降低命中率，只有视觉上相似的块不会误命中。

复现：

```text
python tools/benchmark-mangajanai.py MODEL.onnx REPORT_DIR --compare-release134 --sample blank
python tools/benchmark-mangajanai.py MODEL.onnx REPORT_DIR --compare-release134 --sample dense
python tools/benchmark-mangajanai.py MODEL.onnx REPORT_DIR --compare-release134 --image PAGE.png
```

Android 设备测试支持 `mangaPage` 参数读取应用私有 files 目录中的实际图片；未指定时使用明确标记的合成图。分别记录冷会话和跨页复用后的整页耗时，输出 within5Seconds；仍直接运行增强，未使用最终图片磁盘命中替代推理。日志标签 `MangaJaNaiBenchmark` / `MangaJaNai`。用户仅提供漫画标题，未提供原图，本次没有该漫画的实际尺寸与速度记录。
