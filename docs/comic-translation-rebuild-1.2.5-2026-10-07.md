# 1.2.5 跟手翻页与漫画翻译链路重构

本轮仍使用 1.2.5 / 206，并替换同一个 Release 的 APK 与校验文件。此前两轮归档保留；本轮产物与验证保存在 `artifacts/release-1.2.5-translation-rebuild/`，其中 `before-ui-tokens/` 保留修复基线前的中间构建。已安装旧 1.2.5 的用户需要手动下载覆盖安装。

## 翻页

原实现为了减少平板翻页行程，把手指位移映射为约 58% 的书页宽度，导致书页抓取点跑在手指前面。现在拖动使用原始像素位移，短行程 / 同向速度阈值只决定松手后完成还是回落。`CurlView.setReleaseCommit` 单独确定目标，收尾动画从实际抓取位置开始，取消手势始终回落。左右快捷点按仍走揭页动画。

## UI 规范检查

用户要求修复原有 UI 字面量检查后，小说与漫画阅读界面的固定字号、行高、圆角、间距和重复叠色迁移到既有 `DesignTokens` / `ReadingPalette`，数值保持原视觉。正文用户字号、全局玻璃与开关动效保持现有行为。带文字标签的装饰图标复用 `PanelDecorativeIcon`，标签和单选状态留在所属控件，不重复朗读。

`tools/ui-gate.ps1` 和基线 JSON 未改，集中令牌自身仍参与统计。最终各项通过：字号 503 / 549、圆角 297 / 327、颜色 289 / 311、空说明 114 / 118、dp 2394 / 2528、sp 581 / 610；列表类型 31 / 27。该检查约束新增散落常量，不能替代视觉和辅助功能验证。

## 翻译

按用户澄清，保留手机端 PP-OCRv6 / YOLO。识别与气泡模型按需下载，翻译大模型在云端，不添加本地翻译模型；仅对白文本发送给翻译服务。

| 问题 | 改动 |
| --- | --- |
| 原图可能在识别过程中被回收 | `scale` 同尺寸可能返回原对象，回收前检查身份；保护 960 / 1472 方页与裁剪复用路径 |
| 模型逐像素读取开销 | 检测 / 识别 / 气泡模型改为 `getPixels` 批量读取，保持通道与归一化算法 |
| 识别异常变成无字成功页 | 传播识别错误，检测完成状态有效；不能永久标记为无字已译 |
| 网络失败重试再次跑 OCR | 原文、语言、行框与气泡几何单独缓存，切换翻译引擎和重试可复用 |
| 旧预取阻碍新可见页 | 取消已离开窗口的工作，调度可见页优先；正常取消不当作失败 |
| 状态提示被底栏遮住 | 按实测底栏高度避让，含系统导航、安全区、章节按钮和字体缩放 |
| 所有失败都叫重试 | 区分 OCR、隐私限制、网络、超时、401 / 403、额度、404、限流与服务故障；永久拒绝立即停止 |
| 重试影响整章缓存 | 只重试当前页；设置类错误直接进入翻译分类 |
| 大模型长时间反复等待 | 每批最多重试一次、最多 20 个对白 / 6000 字；整页 28 秒预算，输出长度有界 |
| 提示词冗长、文风与上下文不清楚 | 改为简洁漫画翻译规则，保留情绪、称谓、拟声词和笑点，利用同页词义上下文但不猜人物关系 |
| 不同漫画混用人物译名 | 译名表按漫画隔离，单漫画跨页复用 |
| 乱码一项导致整页失败 | 严格对应 ID，显式空字符串可跳过乱码；空格、null、重复 / 缺失 / 额外 ID 仍拒绝，未译文字保留原图 |
| 机翻降级被误当成 AI 成功结果 | 大模型瞬时失败可降级腾讯机翻并显示原因；降级结果不写 AI 译文缓存 |
| 配置易填错或保存异常崩溃 | 国内服务预填地址与模型，切换主机清空其他服务的 Key；可选空 Key，不强制存空密钥；真实 Key 必须安全存储，失败反馈 |

两个入口保留：自定义云端大模型 API，以及免费免 Key 腾讯机翻。公开网页机翻没有可用性承诺，界面明确其类型。尚未核实到可稳定用于发布包的免费免 Key 大模型源，不把腾讯机翻冒充大模型。

核实依据：[腾讯混元调用指南](https://cloud.tencent.com/document/product/1823/132252)、[硅基流动 API 文档](https://docs.siliconflow.cn/docs/userguide/capabilities/vision)、[Pollinations 现行认证说明](https://github.com/pollinations/pollinations)。本机对硅基流动官方 chat/completions 不带 Key 的样例请求实际返回 HTTP 401；“有免费模型 / 额度”与“免 Key 调用”是不同条件。

## 验证

- 306 项专项 JVM / Robolectric 测试，39 个套件，0 失败、0 错误、0 跳过；包括真实腾讯 HTTPS 日英翻译与缓存。新增 12 项定义，仓库共 727 项 JVM 定义，设备共 104 项定义；定义数量不是全应用执行数量。
- 39 套件首次运行发现旧空格响应断言与新跳过规则不一致，保留原断言并修复为只接受显式空字符串。首次 4 核限制运行的既有 ANIME4K 计时测试超 8 秒预算（11.588 秒）；最终 8 核限制完整回归通过，测试预算与图像增强代码未改，失败日志保留。
- 手机 / 平板、LTR / RTL、单双页的抓取点位移与松手动画源验证通过；取消不提交翻页。
- 原生 GL / Core / OCR 7 项已通过。首次旧设备用例固定拖动 95dp，低于平板 104dp 慢滑阈值，正确回落却被当作失败；改为实际阈值 +16dp 的慢滑，额外断言收尾目标，未放宽生产判定。最新 UI 代码已重新编译，306 项 JVM 与 7 项设备测试再次全部通过。
- 最新 Debug 包验证平板 1280×800dp 与手机 411×731dp：译文、翻译分类和服务预填布局正常；真实 401 状态可见并避让底栏，点按直接进入翻译分类。
- 真实日英混合样例通过本地 OCR → 腾讯 HTTPS → 4 处气泡译文，首屏 5795ms；在线连接测试 241ms；真实硅基流动无 Key 返回 401，界面显示密钥 / 引擎原因。样例与计时不能代表所有漫画。

## 限制

没有用户真实 AI Key、真实手机连接或大样本竞品 / 人工译稿对照。手机动态尺寸切换时主机 CPU 96%，出现输入 ANR，未计通过；固定手机配置冷启动后阅读与设置复核通过。正式 arm64 包覆盖安装成功、冷启动返回 ok（5226ms），随后 Windows QEMU 宿主 0xc0000005 退出，正式包持续 UI / 长期运行未验证；宿主事件和失败日志保留。自然对白提示词和统一译名能改善调用规则，但不能保证所有 OCR、复杂分镜、艺术字和译文达到专业翻译组水准。现有内存预算与原文区域排版仍保留，失败不抹掉原文。

正式包：1.2.5 / 206，24,073,860 B，arm64-v8a；签名与旧 1.2.5 一致，ZIP CRC / 16KB 对齐、801 项输入指纹一致性通过。SHA-256：`3181a0259111cb8e94831d5446e3a23d043ac7e14b2bd4aa40cdc885519cfe9b`。
