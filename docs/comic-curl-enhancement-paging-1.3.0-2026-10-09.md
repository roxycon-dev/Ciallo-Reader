# 仿真卷页增强期间空白修复 · 1.3.0 / 211

用户反馈漫画开启画质增强后，翻到下一页先空白再显示画面，并确认使用的是仿真卷页。本轮沿用现有图像增强算法，修复页面加载结果进入卷页纹理的时机。

## 原因与修复

- 加载器已经生成正确裁边、拆页和旋转的原图预览，但卷页通知只接收当前页，增强中的相邻页没有进入卷页缓存。现在同步当前、下一和上一跨页的预览及最终图。
- 纹理创建只读取卷页自身缓存，可能早于 Compose 收到预览或最终图通知。现在直接查询共享加载器的精确最终图，随后读取卷页缓存及精确预览，仍保留原有同页变体回退。
- 相邻页增强结束后只填缓存，不刷新已经创建的空白纹理。现在加载完成也通知显示端，纹理刷新在翻页、拖动及自动翻页期间延后；落定后已有可读预览立即补齐。
- 旧跨页的刷新请求曾先移除新跨页的延迟回调，再检查页码。现在先核对当前跨页，旧回调不能取消新页刷新。

最终结果仍优先于临时预览，迟到的预览不会覆盖已完成的增强图。缓存继续遵守现有字节预算，纹理回调只读缓存，不执行网络请求或增强运算。

## 验证范围

新增 `ComicCurlEnhancementPagingTest` 使用真实本地图片和加载器，主动占住增强处理闸门，不依赖处理速度恰好够慢：

1. 遍历四档增强，在最终处理尚未完成时验证下一页纹理已有原图内容；模拟通知尚未处理时直接创建纹理，并检查完成通知、最终图替换与迟到预览拒绝。
2. 共享缓存最终图优先于卷页中的旧预览。
3. 双页 RTL、独立左右半页和 90° 旋转在增强等待期间仍保持正确页图。
4. 纹理刷新等待翻页结束，旧页回调不会取消新页待刷新的纹理。
