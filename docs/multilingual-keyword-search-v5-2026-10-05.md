# 多语言搜索 v5：洛琪希简称与完整查词路径

用户已开启代理，搜索“洛琪希”显示“未找到更多可靠名称”。复现发现 Bangumi 请求成功，返回 `ロキシー・ミグルディア・グレイラット`、`Roxy Migurdia Greyrat`、`洛琪希·米格路迪亚·格雷拉特`；此前匹配只接受整个名称相等，因此排除真实候选。此前 v4 真实接口探针只覆盖两个完整名且带类型提示，不能证明简称可用，这是验证覆盖的遗漏。

## 修复

- 结构化中文人名中间点前的名字部分（2–6 汉字）可作为简称；仅角色 / 人物可用。完整名称或别名优先，姓氏、任意前缀或作品标题不适用。同一简称对应多个候选时拒绝自动扩展。
- 本地词典 SQLite v3 增加独立 `name_parts` 索引，短名唯一时读取实体的完整名称；不往显示词表塞推测词。在线资料更新与别名 / 名字索引同一事务切换。
- 旧 SQLite v2 的可重建词典自动重建。持久查询缓存 v3 保留 v1 / v2 的可靠名称，但丢弃旧规则的提供者决定、标记待刷新；升级后不继续等待旧“空结果”的重试期限。用户书库不迁移。
- Bangumi 人物 / 角色读取前 5 个结构化候选，按完整名 / 明确简称分级，多个同级匹配不采用首条。原词、本地优先、最多 6 查询、隐私规则和普通书源字符串保持一致。

真实接口探针现在以未知类型查询雪之下雪乃、渡航和洛琪希，不额外提示人物类型。新增真实生产 `KeywordRepository` 验证：输入“洛琪希”，发布 `roxy migurdia`、英文与日文完整名；状态“已在线补充并缓存”；关闭在线后新仓库仍取到英文完整名、状态“已使用缓存”。摘要见 `artifacts/multilingual-search-v5/live-api-results.json` 和 `live-repository-results.json`。
