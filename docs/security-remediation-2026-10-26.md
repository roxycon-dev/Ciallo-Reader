# 1.5.6 安全修复与检测记录

版本为 1.5.6 / 248，Android 7+，ARM64。正式包名仍为 `com.aistudio.novelreader.kxmpzq`，成人源及默认启用方式、用户确认后的系统安装功能保留。已合入动效与 Z Fold 会话今天完成的 `adc0d9236636e1660ee72191f20f604331e438d2`，没有修改原会话工作区。

## 安全修复

- JSON 与 JavaScript 书源不再允许 `insecureTls` 关闭证书和主机名验证。旧配置可以继续读取，连接仍需通过验证；爱漫画限定 CA 的兼容路径保留。
- 带 Cookie 或 Authorization 的请求不能通过 HTTP 发送，包括 HTTPS 跳转到 HTTP。匿名 HTTP 请求仍按现有网络策略处理。
- 旧发布证书对应的私钥条目存在于公开 Git 历史，正式发布改为独立的新固定密钥。最终包不携带旧证书历史，不继续授予旧证书的签名权限、共享 UID 或回退能力。新私钥和受 DPAPI 保护的密码留在工作树外。
- 更新器仍要求完整一致的当前签名集合，同时校验官方资产来源、版本、大小和可用的摘要。Android 9/10 的安装包签名读取同时请求两种平台签名标志。不放宽校验来接受旧密钥或签名历史。
- 资产按 Git 原始字节检出，防止宿主系统的自动换行转换改变打包内容。全部源资产保留；测试用 TLS 私钥不能进入 APK。

旧材料暴露不等同于已经发现恶意签署，也不能独自证明厂商分类的全部原因。公开证据、新指纹、构建门禁及迁移流程见 [签名说明](app-signing.md)。

## 数据迁移与功能验证

保留旧历史的实验包曾在 API 30 / 35 上成功覆盖原版，保留 UID、首次安装时间和私有测试文件，并拒绝旧签名回退。但它仍报风险，**不作为最终发布方案**。

完整退休旧签名不能继承旧安装身份，所以首次迁移必须：在旧版导出备份 → 确认文件保存在应用目录外且可读取 → 卸载旧版 → 安装新版 → 导入备份。不能把不同签名版本描述成可以直接覆盖升级。之后相同新密钥的版本按正常更新流程处理。

方案确定后，最终 53 项回归全部通过，0 失败、错误、跳过：TLS 7 项、更新安装包校验 14 项、便携备份导入导出 25 项、成人源默认值 3 项、画质动效分档 4 项。静态 APK 校验脚本保留对不同签名覆盖升级的拒绝。动效提交原有 145 项 JVM 与 19 项 Android 回归记录见 [动效验证报告](performance-stability-2026-10-26.md)，不把模拟窗口测试冒充三星实体折叠屏测试。

最终 Release / R8 / Vital Lint、ZIP CRC、16 KiB 对齐及 v2/v3 新固定证书验签通过。系统安装实测明确拒绝旧签名覆盖为新签名；新密钥同版本重装保留 UID、首次安装时间和私有测试文件。启动和主页冷启动检查通过，未观察到 AndroidRuntime 崩溃；这不是 HarmonyOS 真机验证。

最终 APK：29,233,184 字节，SHA-256 `81504fea9264ce6f4a90c4eb6e59640413c4f4d1db56bbfcd2457738b2e8daee`。最终包没有旧签名历史和测试私钥；43 项源资产集合保留，文本换行归一化后全部与原包一致。Release 提供校验与验证附件，不覆盖原 1.5.5 附件。
