# 神回窗口封面加载修复（2026-10-05）

仅调整神回添加 / 编辑窗口的图片请求与显示策略。阅读器的预取、网络拦截器、缓存容量与翻页行为保持原有配置。

## 解决的问题

- 切换选中页时，原先所有缩略图共用 `selectedBitmap`，新选中位置会暂时显示上一页的图。现在每个格子独立持有对应页面的缩略图；大封面状态也按来源重新初始化，旧请求结果不会成为新页封面。
- 原先选中状态是加载协程的 key，选中会取消该页下载，并跳过其缩略图请求。现在选中只控制边框；失败可点按该位置重试。
- 点按候选不再自动横向重排 / 滚动，打开时仍定位当前阅读页。

## 加载策略

- 使用阅读器相同的 URL / 请求头 SHA-256 缓存标识、FIT / INEXACT 解码，复用阅读器内存和磁盘缓存。
- 缓存命中不等待网络名额。空缓存不执行 `only-if-cached` 请求，避免冷启动探测的 504 触发书源重试。
- 神回专用网络名额为缩略图 3 个、大封面 1 个；同页请求按 key 合并，后续请求在取得锁后重新读取缓存。
- 可见缩略图随 LazyRow 加载，使用已有漫画加载器的请求级渐进 JPEG 预览；不新增第二条下载，不把不完整字节写入缓存。加密 / 图片转换源和其它格式仍等待正常解码结果。
- 缩略图保留 12 MB LRU；大位图先裁剪长条漫中段、缩至长边 320 px，再进入缩略图缓存。
- 取消异常正常传播；窗口关闭 / 页面离开组合取消对应请求。渐进结果回到主线程且不能覆盖最终结果。封面未就绪时暂不可保存，取消窗口仍可操作。

## 验证

30 项 JVM / Compose Native 回归全部通过：9 项神回组合与加载、10 项神回界面截图、7 项阅读器加载可靠性、4 项缓存 / 并发辅助逻辑。另有 8 项更新检查、3 项首次启动与 68 项书架静态检查通过。

新增用例实际覆盖阅读器内存和磁盘缓存零追加下载、并发缩略图与大封面单次下载、只有一张加载成功时反复选择其它页且位置不变 / 请求不中断、失败点按重试、长条漫中段与内存尺寸上限。编辑失败的新页不会借用已保存封面，重试同时恢复缩略图与大封面。浅色窗口截图已查看。

API 33 与 API 35 Native 绘制在同一 Robolectric worker 会出现字体 ZIP 挂载冲突；阅读器 API 35 组改为独立 worker，最终每组 XML 的 failures / errors / skipped 均为零。首次启动测试补齐其缺少的 WorkManager 初始化并使用 Native SQLite，生产启动逻辑保持原有行为。

全局 UI gate 的字面量计数与本次改动前相同，仍超过仓库旧基线；未增加计数或调整基线。真机网络首图时间需安装包验收，本地测试不代替实际图源测速。
