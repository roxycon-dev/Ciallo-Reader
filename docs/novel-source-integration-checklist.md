# 小说书源接入检查与验收清单

适用项目：Ciallo Reader。适用于内置小说源、JSON / Legado 导入源、整本文件下载源和逐章生成 EPUB 的源。

**目标：确认书源在声明的功能、作品范围和网络环境内实际可用；遇到不完整内容能明确失败，不能把残缺书标成下载成功。** 第三方站点会变更，有限样本无法保证永久可用、覆盖全部作品或源站原文绝无缺漏。

使用方法：接入前建一份验收记录，按本文逐项填写“通过 / 失败 / 不适用”和证据。未执行项填写“未测”，不能算通过。不适用必须说明理由；声明支持的能力不能以“不适用”跳过。

## 1. 先写清接入范围

- [ ] 记录网站原名、实际域名、源 ID、接入日期和适配版本。显示名使用原站名称或明确的站点标识，不能把聚合站冒充首发站。
- [ ] 分别声明支持搜索、详情、完整目录、在线文字、整本下载、正文插图、更新检查的哪些能力。不要因为有章节接口就声明完整在线阅读。
- [ ] 区分原创、翻译、机翻、同人及站内不同版本；保留来源说明，不能把机翻标成人工翻译。
- [ ] 说明可访问范围：仅公开作品、公开章节或整本公开作品；含锁章作品如何处理。
- [ ] 记录网络条件、是否使用代理、是否有地区限制、是否依赖浏览器验证。通过代理验收不能写成所有网络均可直连。
- [ ] 明确免登录要求：搜索、详情、目录、正文、插图、下载每一环都不能依赖账号、订阅或已有登录会话。

**判定：** 范围不清、只能打开首页、只找到书单或尚未拿到正文，均不能称为“书源可用”。

## 2. 选样不能只挑容易成功的书

建议每源至少选 5 本不同作品，按站点实际功能覆盖下表；同一本可覆盖多个特征。数量只是起点，解析分支、模板或下载格式不同，必须补充相应样本。

| 样本 | 重点检验 |
| --- | --- |
| 短篇完结作品 | 所有章节、结尾及整本流程 |
| 长篇或多卷作品 | 目录分页、分卷顺序、长章、内存与耗时 |
| 连载作品 | 最新章、更新时间、目录变化、增量更新 |
| 含正文插图的作品 | 非封面图片、图文顺序、离线解码 |
| 标题或排版复杂的作品 | 同名书、别名、繁简体、番外、特殊字符 |
| 锁章或失效作品 | 明确拒绝，不能默默跳过后成功 |
| 搜不到的关键词、失效 ID | 真正空结果与站点失败的区别 |

站点无插图、无分卷等情况可以记为不适用；站点存在这些内容却没选样，属于未测。不要用另一本同名书、其他版本或更短的镜像替代指定资源后声称通过。

## 3. 搜索与作品身份

| 检查什么 | 怎么检验 | 通过标准 |
| --- | --- | --- |
| 搜索确实有效 | 分别输入完整书名、部分书名、作者、繁简体与特殊符号；按声明的搜索能力选择必测项 | 返回与输入对应的结果；不把首页推荐当搜索结果 |
| 空结果与失败 | 搜索随机不存在的词；模拟超时、403、验证页和接口结构变化 | 真无结果才返回空列表；访问/解析失败明确报错 |
| 搜索分页 | 查看原站是否多页，核对第二页、最后一页和重复结果 | 声明支持的分页可以继续加载；只取首屏时说明限制 |
| 作品没有串书 | 比较书名、作者、原站详情链接、稳定资源 ID、版本/卷标识 | 搜索 → 详情 → 目录 → 下载始终属于同一资源 |
| 卡片可见性 | 对比源站页面可见卡片与响应 DOM | 不把隐藏占位、广告、模板节点或反射搜索词的假卡当书 |
| 源 ID 与作品 ID 稳定 | 重启、重复搜索、刷新、换排序后对比 | 不使用列表下标、临时签名或每次变化的 URL 参数作为唯一身份 |

## 4. 详情与完整目录

- [ ] 标题、作者、简介、状态、卷数/章数、最新章来自真实字段；缺失值保持缺失，不编造“完结”“已同步”。
- [ ] 找到全部目录入口，包括“展开全部”、目录分页、分卷、折叠目录和接口游标；不是只抓详情页的“最新章节”。
- [ ] 与原站完整目录逐项比较：**稳定章节 ID、标题、卷标识与顺序**。只比较总数量不够，同数量也可能重复或串章。
- [ ] 正序、倒序、分卷重置编号、序章、后记、番外、公告都经过识别。不要把目录行号当正文章节号。
- [ ] 分页合并有终止条件、已访问页/游标去重与循环检测；不能无限循环，也不能遇到一次空页就默认为完结。
- [ ] 检查分页交界处是否漏章或重复；去重只按确认过的资源身份，不能按相同标题误删不同卷章节。
- [ ] 数字跳号仅作为线索，结合原目录核对；正常分卷、拆章和番外不能被误判为缺章。
- [ ] 下载开始保存目录快照；下载结束重新读取目录，比较 ID、标题和顺序。发生变化时按明确策略重试或提示，不能悄悄混用两个版本。

**判定：** 未抓全目录、顺序无法确认、锁章被过滤掉，或目录变化未处理，不通过整本下载验收。

## 5. 正文：能显示文字不等于完整

| 检查什么 | 怎么检验 | 通过标准 |
| --- | --- | --- |
| 正文边界 | 对照原站阅读页检查提取容器及首尾段落 | 无导航、广告、评论、推荐列表混入；不截去正文 |
| 章节内分页 | 找含“下一页 / 本章未完”的长章，追到该章末页；区分“下一章” | 所有页按顺序合并，不只保存第一页、不重复或吞掉交界文字 |
| 动态内容 | 比较初始 HTML、站点实际接口和最终可见正文 | 不把加载占位当内容；无法取得完整正文则明确失败 |
| 编码 | 检查响应头/BOM/页面声明及实际文本，验证简繁汉字、标点、emoji、生僻字 | 无因错误解码产生的乱码、NUL 或未还原的加密字形 |
| 文本节点 | 测试嵌套 span、br、段落、实体、空行与内联图 | 内联文字不丢失，段落和图文相对顺序保留 |
| 清洗规则 | 对比清洗前后正文，查看每条删除/替换规则命中位置 | 只移除已确认的页面附属内容，不以宽泛正则删除真实正文 |
| 截断与占位 | 检查首段、中段、末段、异常短章及“处理中 / 加载失败 / 缺译”等提示 | 已知缺章占位、试读截断或空章明确失败，不删除提示后继续冒充完整 |
| 真正内容完整性 | 将来源正文的逐章有序段落与 EPUB、入库内容分别比较 | 标准化只处理约定的空白/换行，不能忽略真实汉字和标点差异 |

**必须区分两类缺字：** 错误编码产生的损坏，与源站原文就含有的字面缺字。若允许少量原文缺字，应记录位置、数量与依据并保留原样，明确列为例外；不能声称“无乱码无缺字”，不能猜字补文。当前 `GuestNovelIntegrity` 对 EPUB 有有限的原文缺字容忍，逐章 HTML 和 TXT 的规则不同，不能混称统一零缺字。

不要仅凭“中文占比高”“没有 U+FFFD”“字数差不多”判为完整。源站与下载器共用同一错误解析时，自行生成再比较哈希也可能一起错；必须另行对照原站可见正文/独立接口响应的首尾、分页交界及代表性章节。

## 6. 插图、封面与离线资源

- [ ] 封面和正文插图分别验证；封面正常不能证明正文图片正常。
- [ ] 检查懒加载字段、相对 URL、签名有效期、Referer、User-Agent 和重定向；免登录源不能借用其他源的账号 Cookie。
- [ ] 每张正文图片下载后实际解码，拒绝 HTML 验证页、空文件、截断图和只返回 200 的错误响应。
- [ ] 分别记录“独立图片文件数”和“正文引用次数”；同一图片多次出现时，去重文件不能删掉正文引用。
- [ ] 图文混排顺序与来源一致，图片不全部挪到章尾；图片章节不能因没有文字而被误删。
- [ ] EPUB 内引用均指向包内有效资源，支持嵌套 OPF、相对路径及带空格/中文的路径；不依赖已删除的解压缓存目录。
- [ ] 测试导入完成并清理临时文件后，再冷启动、断网打开至少一张非封面正文插图，确认实际解码和显示。
- [ ] 在线文字能力若不能呈现完整插图，不应声明“完整图文在线阅读”；应准确说明使用离线 EPUB 的阅读方式。

## 7. 整本下载与文件验证

- [ ] 通过应用实际 `DownloadManager → DownloadWorker` 发起下载，而非仅用桌面脚本保存文件。
- [ ] 检查格式、文件头、实际大小和响应内容；不能把登录页、错误 JSON、压缩包外壳或试读页命名为 EPUB/TXT。
- [ ] 逐章生成文件时，每个目录项都成功获取；任何章或必需插图失败，整本不得标为完成，不得留下可误读的半成品。
- [ ] 检查临时文件提交顺序：下载、格式/完整性校验、导入全部成功后才显示完成；失败不覆盖旧文件、不新增空书架记录。
- [ ] 对整本 EPUB 检查 ZIP 实际长度与 CRC、重复条目、container/OPF、manifest/spine、正文和插图引用、编码及空章；不能只判断 ZIP 能打开。
- [ ] 目录型源将 EPUB 正文章节与完整源目录逐项对应。目录导航页、长章入库拆分造成数量差异时给出映射依据，不只放宽数量断言。
- [ ] TXT 检查实际编码、可识别章节编号、重复/空章、开头及结尾；没有可靠目录的 TXT 必须说明无法证明整本完整，不能把未检测出跳号等同于没有缺章。
- [ ] 记录整本 SHA-256、源目录、逐章标题/段落数/正文哈希、图像数等，便于定位损失发生在下载、转换还是入库。
- [ ] 区分传输完整与原文完整：CRC/SHA-256 相同证明字节未变，不能证明源站提供的是全本。

## 8. 入库与生产阅读器

- [ ] 在实际书架中打开，核对书名、作者、来源 ID、资源 ID、格式及章节顺序。
- [ ] 将完整导出内容与数据库逐章/有序段落对照。仅用“某段在全书字符串中出现”不足以排除串章、重复或顺序错误。
- [ ] 在生产 `ReaderScreen` 打开正文首章、中间章、末章、长章分页交界及含图章；不能用自制 HTML 预览替代实际阅读器。
- [ ] 等待正文异步排版完成再截图，人工检查可读文字与插图；非空白像素或多种颜色不能单独证明正文正确。
- [ ] 验证目录跳转、上一章/下一章、末章结束、长章滚动/翻页、阅读位置保存和重开恢复。
- [ ] 断网并重启应用，确认已下载正文与包内插图仍可阅读，而非命中在线缓存假装离线。
- [ ] 如声明支持在线阅读，同样单独验证在线打开、翻章、错误重试与插图，不能以离线成功代替在线验收。

## 9. 失败、取消与更新：不能只测成功

| 注入情况 | 必须检查的结果 |
| --- | --- |
| 超时、断网、429、5xx | 有界重试/退避、可取消；不会无限等待或重复刷请求 |
| 401/403、登录页、验证码页、付费锁章 | 说明真实原因；免登录源不能把这些情况转成要求登录的成功流程 |
| 中间某章为空/少一页、插图损坏 | 整本失败；错误能定位到具体阶段，不能跳过失败项 |
| 下载时目录新增/删除/改序 | 重新核对并按策略处理，不导入混合目录 |
| 用户暂停、取消、应用进程重启 | 状态和临时文件正确；恢复行为符合实际实现，无重复任务或幽灵完成 |
| 磁盘不足、目标文件写入失败 | 不显示成功、不损坏旧书，有可理解的错误 |
| 同一本重复下载、多个任务并发 | 不串资源、不重复入库、不共享错误的临时文件 |
| 连载更新成功 | 新章与原书正确关联；书签、标注、进度、阅读历史按策略保留 |
| 更新下载或导入失败 | 原书正文、文件、进度、书签和标注保持可用；不先删除旧书再尝试下载 |

逐章重新生成 EPUB 与字节范围续传是两种实现。当前 `GuestNovelEpub` 暂停后重新生成，不能写成已完成章节永久保留或通用断点续传。

## 10. 项目接线是否完整

以下是当前项目的检查入口，并不意味着新增任意一个配置就自动具备所有能力。

| 入口 | 检查事项 |
| --- | --- |
| `BookSource`、`SearchBook`、`DownloadInfo` | ID、格式、请求头、详情/分享地址与错误返回正确；分享地址是作品详情页 |
| `SourceCapabilities` | 小说不误归为漫画；真实声明 `supportEbook`、`supportOnlineText` 和登录需求 |
| `PublicNovelSources` / `PublicNovelSource` | 逐章整本源的工厂、站点分支、ID 解析、搜索、详情、目录和正文均接通；生产注册只纳入通过验收者 |
| `WholeBookNovelSources` | 新源能进入整本小说下载、更新、源关联与校验流程；单独实现的源不能漏加必要接线 |
| `LibraryViewModel` / 书源管理 | 注册后能在真实界面启用、搜索、查看详情和发起下载；默认开关与用户既有选择不冲突 |
| `DownloadWorker` / `GuestNovelEpub` | 生成式 EPUB 路由确实命中正确适配器；内部标记 URL 不被当成真实 EPUB 直接请求 |
| `GuestNovelIntegrity` / 导入器 / `ReaderScreen` | 完整性校验实际执行，导入与正文图片路径正确，完成状态在真实可读后出现 |
| `JsonBookSource` / `SourceImporter` | JSON、Legado 兼容是受限实现；逐条验证实际用到的规则、脚本、分页和正文能力，不假设全部语法兼容 |

免登录源还应检查请求不混入其他源的凭据；响应、跳转域名、请求体积、下载体积与超时有边界。日志不得包含账号、Cookie、授权头或带签名的私人下载链接。不要以关闭 TLS 校验作为接入修复。

## 11. 执行测试时防止“假通过”

现有参考文件：

- [真实搜索、整本下载与段落审计测试](../app/src/androidTest/java/com/example/source/PublicNovelSourceDeviceTest.kt)
- [完整性及拒绝路径测试](../app/src/androidTest/java/com/example/source/GuestNovelIntegrityDeviceTest.kt)
- [真实下载内容的阅读器测试](../app/src/androidTest/java/com/example/source/PublicNovelReaderDeviceTest.kt)
- [免登录小说源验收实例](novel-guest-sources-verification-2026-10-19.md)
- [插图路径与原文缺字问题实例](novel-illustrations-repair-2026-10-19.md)

执行前检查：

- [ ] 新源有自己的实网用例和样本，现有测试通过不代表新源已经测过。
- [ ] `PublicNovelSourceDeviceTest` 的实网测试需要 `livePublicNovel=true`；未传参数时部分用例直接返回，JUnit 绿色不能作为实网验收证据。
- [ ] 阅读器测试依赖先前真实下载的审计书籍。先明确执行下载测试，再执行阅读器测试；不假设测试框架的类/方法顺序。
- [ ] 区分 fixture 解析测试、实网测试、生产下载/入库测试和实际阅读验证；它们相互补充，不能互相替代。
- [ ] 记录发现、实际执行、通过、失败、忽略及提前返回的数量；失败实验不能改成忽略后仍称“全部源通过”。

PowerShell 示例（仓库根目录执行，先确认目标设备）：

```powershell
# 编译设备测试；x86_64 模拟器需显式包含该 ABI
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest -PincludeX86

# 先跑真实下载/入库审计；新增源需先加入自己的用例
.\gradlew.bat :app:connectedDebugAndroidTest -PincludeX86 "-Pandroid.testInstrumentationRunnerArguments.class=com.example.source.PublicNovelSourceDeviceTest" "-Pandroid.testInstrumentationRunnerArguments.livePublicNovel=true"

# 上一步下载样本成功且数据仍保留后，再执行实际阅读器测试
.\gradlew.bat :app:connectedDebugAndroidTest -PincludeX86 "-Pandroid.testInstrumentationRunnerArguments.class=com.example.source.PublicNovelReaderDeviceTest"

# 完整性拒绝路径和相关桌面回归
.\gradlew.bat :app:connectedDebugAndroidTest -PincludeX86 "-Pandroid.testInstrumentationRunnerArguments.class=com.example.source.GuestNovelIntegrityDeviceTest"
.\gradlew.bat :app:testDebugUnitTest --tests "com.example.download.CorruptedFileTest" --tests "com.example.download.BackendDownloadPolicyTest" --tests "com.example.download.BackendDownloadWorkerTest" --tests "com.example.source.SourceResponseTest"
```

确认 Gradle 没有复用旧测试结果：检查本轮日志、时间戳、样本审计文件和真实请求记录，必要时使用 `--rerun-tasks`。构建或设备连接失败属于未执行，不能记为书源失败或成功。GUI 手动验收同样需要记录具体资源与操作结果。

## 12. 发布前最后一关

- [ ] 所有声明能力的必测项通过；未测范围在说明中明确列出，未满足核心链路的候选不进入生产可用列表。
- [ ] 至少完成真实搜索 → 详情 → 完整目录 → 整本下载 → 校验 → 入库 → 实际阅读 → 断网重开；目录型源同时留下章节与内容对照证据。
- [ ] 至少验证一次锁章/缺章/损坏文件拒绝，以及已有书更新失败后的数据保留。
- [ ] `:app:assembleRelease` 成功，相关检查和回归通过；验收记录对应最终源码版本。打包后不再修改适配器却复用旧结论。
- [ ] 校验最终 APK 的版本、包名、ABI、签名、SHA-256，以及实际包含的新源名称/配置；安装目标构建检查新源入口。仅在模拟器测试时，明确未做实体手机验收。
- [ ] 源显示名、文档、README 与能力声明一致；不得承诺所有作品、全地区直连、全平台最快或永久可用。
- [ ] 保存可复核的非敏感证据；不要把完整书籍、账号数据或私人签名 URL 提交到公共仓库。

**不予启用的情况：** 登录依赖未排除、只验证首页/搜索、未抓全目录、只下载首章、正文或插图不完整、没有生产入库与阅读验证、失败时仍标记成功、更新破坏原书。非核心可选能力失败时，应关闭对应能力并重新验收剩余范围，不能静默降级后仍宣传原有能力。
