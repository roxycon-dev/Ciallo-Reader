# 小说插图、Novelia 下载与隐藏书卡修复（2026-10-19）

修复在 1.4.8 / 231 工作区验收，随后按用户要求升级为 **1.4.9 / 232** 发布。三个用户指定资源分别验证，不以相似书名替代。见 [发布说明](release-1.4.9-2026-10-19.md)。

## 原因与改动

- Android 的 `/data/user/0/<package>` 与 `/data/data/<package>` 指向同一目录。EPUB 正文文件经过 canonicalize，而解压根目录没有同步转换，生成的包内图片路径含 `../../.../cache/epub_<time>/`。临时目录删除后，图片引用无法匹配 ZIP 条目。
- 新导入对图片与根目录统一 canonicalize 并校验包含关系；阅读器识别已有引用中的特定旧临时目录前缀，只在 ZIP 内归一化，不提取外部文件、不改章节和进度。正文、预热、全屏、保存共用解析函数。
- Novelia `hameln/387502` 的原始 EPUB 与章节 API 均在第六章同一段包含一个字面 U+FFFD。UTF-8 编码有效，服务器没有提供其他译文。旧校验因这一个缺字拒绝整本；现允许每个至少 1,000 字符的章节至多一个、全书至多三个字面缺字符，内容保留原样，不猜测补字。无效 UTF-8、NUL、密集缺字、空章、缺译占位、目录不一致、CRC 与插图损坏仍拒绝；NUL 在 HTML 解析前检查，防止被解析器吞掉。
- Z-Library 反映搜索词的假卡位于明确隐藏的 DOM 子树。沿用本次工作区已经实现的布局选择前统一过滤，避免 GenericFallbackParser 再引入；可见同名版本不按标题/作者猜测删除。

## 验证与限制

- 22 项 JVM/Robolectric 回归通过，覆盖图片解码、导入与迁移、根/嵌套 OPF、路径越界、隐藏卡过滤，以及有效源站缺字与真正损坏内容的区分。
- 测试 fixture 改用有效 PNG 与原生图形解码；Windows 上的 Android 文件 URI 使用当前盘根路径测试适配，生产 Android 路径不受影响。
- 实网测试使用模拟器已有系统代理，不据此承诺各地区无需代理。书内的源站缺字没有被自动翻译或杜撰。
- 账号、Cookie、带签名下载链接和完整书籍不放入交付目录。旧《无职转生未来日记》指定资源仍没有取得有效文件，不能用其他书的成功声称它已经下载；其隐藏假卡已过滤。
