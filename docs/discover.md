# 发现 / DISCOVER

入口：底部导航「书库 → 发现 → 书架 → 统计 → 设置」。Android 原生 Compose 实现；没有新增依赖；1.3.7 发布版本与验证记录见 [发布说明](release-1.3.8-2026-10-14.md)。

## 数据与聚合

`ComicSource.discover(DiscoverQuery)` 是独立于搜索的推荐接口。更新、热议、榜单、点击分别查询、缓存和排序。未提供的值使用 `null`，界面显示「未提供」。默认接口返回 `supported=false`，不会把普通搜索结果冒充推荐。

聚合先在每个源内按当前维度排序，再计算稳定的源内名次分数：`1 / (1 + 0.08 × (名次 - 1))`；等指标同分，分页不改变旧条目的分数。每个源具有相等贡献上限；同一作品同一源的多个版本只有一次贡献。跨源贡献求和除以参与源数；不混入其他维度的指标。大站的绝对流量无法压制小站的同等级作品。

去重优先使用带命名空间的可信 `canonicalId`，其次使用 NFKC 规范化的标题、原站别名和兼容作者。存在冲突的作者 / 可信身份时保留不同作品；未知作者不连接有歧义的同名作品。无法辨认的跨语言作品需要书源提供标准身份或别名，不能凭猜测强行合并。

聚合作品保留参与源的分项数据。点击显示选源底部面板，包括更新时间、讨论数、点击量、源内名次、最新话和状态；选定后进入现有详情 / 阅读器。N 个源可读指当前发现数据中确认的源数。点击量和讨论数展示已提供的真实数值之和，排序使用稳定源内名次分数。

每批最多 3 个源并发，每源总超时 25 秒。结果按完成顺序发布；源增删 / 启停和维度切换取消旧请求。每个源独立分页；失败暂停该源自动加载，手动重试原页；其他源继续。已结束的源不重复请求。游标分页沿用原 token；连续两次没有新作品或重复 token 时停止，防止原站重复页导致循环。刷新保留尚未返回的各源内容，成功后独立替换。

缓存保存在独立 SharedPreferences，最多 24 个查询，每查询 300 条，有效期可选 6 / 24 / 72 小时。失败保留已缓存的数据；禁用或删除的源不再参与缓存结果。关闭缓存会立即清空。

## 当前适配

| 来源 | 更新 | 热议 | 榜单 | 点击 |
| --- | --- | --- | --- | --- |
| MangaDex | 官方章节 publishAt；最新 / 今日 / 近三天 / 周一开始的本周 | 未提供 | 原生热门 / 新作 / 完结；飙升未提供 | 未提供 |
| Venera JS 显式 discover 接口 | 按协议 | 按协议 | 按协议 | 按协议 |
| Venera 原有 explore | 「最新」接受原站更新排序；今日 / 近三天 / 本周必须有可解析时间 | 时间范围无法确认时不参与 | 标题明确对应热门 / 飙升 / 新作 / 完结的原生排行榜 | 明确点击 / 阅读量列表；日 / 周 / 月另须有匹配时间窗口名称 |
| 其他漫画源 | 默认缺失，可覆盖接口扩展 | 同左 | 同左 | 同左 |

MangaDex 更新以章节发布时间为准，缺失维度不产生网络请求；这些契约另有 HTTP 拦截器测试。MangaDex 参数以[官方 API 枚举文档](https://gitlab.com/mangadex-pub/mangadex-api-docs/-/raw/main/3-enumerations.md)为依据，复用原有网络与详情 / 章节实现。当前没有对全部第三方书源做实时联网验收。站点未提供的数据无法由客户端创造。

## JS 源扩展协议

```javascript
discover = {
  load: async function ({ dimension, range, page }) {
    // dimension: updates / discussion / ranking / clicks；page 从 1 开始。
    return {
      supported: true,
      hasMore: false,
      entries: [{
        id: "source-local-id", title: "作品名", author: "作者", cover: "https://...",
        tags: ["冒险", "校园"], status: "ongoing",
        alternateTitles: ["原名"], canonicalId: "anilist:123",
        updatedAt: 1791820800000, latestChapter: "第 12 话",
        discussions: 12345, clicks: 567890,
        growth: 12.3, rank: 4, rankChange: 2, newEntry: false,
        hotComment: "原站提供的热评摘要"
      }]
    };
  }
}
```

返回值也接受 `book` 包裹的作品字段。更新时间接受毫秒 / 秒时间戳或 ISO 日期；数量仅接受真实整数；增长为百分比，名次升降为正升负降。范围字符串为界面显示值，接口必须返回对应时间范围的数据。某范围不支持时返回 `supported=false` 与说明；不得用总量冒充日榜、或用热门冒充点击。

分类 ID 稳定，中英文标签与原源「分类：标签」映射见 `DiscoverTaxonomy.kt`。同一作品可命中多个分类。同一一级内多选取 OR，不同一级间取 AND。选择父类包含全部后代；选择具体子类时移除该路径的父类，避免父类覆盖子类过滤。未知标签不凭标题推断，仍保留原标签供展示。繁简/全半角归一，支持复合标签分隔，作者/角色命名空间不作为题材。Action / Fantasy 等宽泛词只映射父类，不误标成战斗 / 魔法。

各级有「全部」；横向滑动，选择摘要可清除。分类数量与今日更新标记基于当前源、当前维度已加载的去重作品，而非书源全库推算值。切换维度、源、返回页面和重启保留选择。关闭成人内容同时清除成人分类选择；已知成人源按现有 JsSourceRepo.ADULT_KEYS 隔离，缺少作品标签也不会绕过默认隐藏。

## 浏览与设置

列表 / 双列网格 / 大图布局持久化。榜单使用列表，前三金银铜渐变名次章与描边。点击进详情；长按弹出附近快捷菜单（追漫、读最新话、屏蔽、分享），背景压暗，菜单受屏幕边界约束。右滑追漫、左滑屏蔽；列表空白区域横滑切换维度。卡片的「已追」跨聚合源识别，取消追漫作用于实际已追的源。

单独书源直接打开，聚合多源先选源。随机从当前筛选结果选择并读最新话，章节接口失败回到详情提供重试。分享复用 `FavoriteShareHelper`，仅打开系统分享选择器。今日追更从现有收藏快照计算；未读按最新话与当前阅读进度判断，入口可直接显示收藏快照里的未读作品。

顶栏点击回顶，随滚动收缩 / 恢复；书源与维度常驻，分类随列表滚动移出。下拉刷新复用系统刷新手势，看板娘指示器；滚动时随机按钮收缩并按方向隐藏。初次前 6 张卡片错峰进入，其他项直接显示。动效遵守减少动画设置，触觉遵守全局开关。

轻度个性化仅对当前维度分数差不超过 8% 的相邻两项，按未读追更、已知作者和阅读历史调整；每项最多移动一位，榜单和原站顺序保持原位，不把多个维度加权混合；屏蔽总是生效。浏览休息提醒只在前台 RESUMED 生命周期计时，默认 30 分钟，可关闭。

设置页末尾「发现与推荐」：默认源、默认维度、布局、个性化、成人内容、提醒开关与 15 / 30 / 45 / 60 分钟间隔、涨跌色交换、缓存开关与时长、清缓存、逐项 / 全部解除屏蔽、清除分类记忆。使用统一 `AppSwitch`。

## 视觉约束与验收边界

主色引用 MaterialTheme；黑白文字按对比度选择。独立语义色、金银铜使用需求指定值。玻璃白 62% / 黑 48%，24dp 模糊，白 40% / 12% 描边；依据壁纸平均亮度和次文字对比度提高卡片不透明度，上限 88%。低画质沿用项目的无实时采样降级。

间距 16 / 12 / 10dp，点击区至少 48dp；卡片使用最小高度与自然增高，适应 130% 字体。原需求「列表 112dp、封面 96dp、上下内边距 10dp」无法同时成立，本实现卡片至少 116dp；第 1 名封面 118dp 的卡片至少 138dp。390dp 双列卡片宽 174dp，3:4 封面高 232dp，因此常见 844dp 高屏幕首屏不会出现三整行网格。

文字辅助透明度 44% 与辅助对比度 3:1 在白底上也不能同时成立；本实现数据辅助文字提高到 64%，优先可读性。平均壁纸亮度不等同于逐像素对比度，彩色主题浅底和壁纸局部高光仍需真机视觉验收。图标复用现有 Material outlined 图标集，尚未替换成统一 1.75dp 描边定制图标。

专项测试与截图：`DiscoverEngineTest.kt`、`DiscoverViewModelTest.kt`、`DiscoverUiTest.kt`、`MangaDexDiscoverTest.kt`。截图使用明确的测试书源，无演示数据进入生产。最终执行结果见本轮任务回执及 PROJECT_GUIDE 新增章节。

## 发现审查返工（2026-10-13）

- 新增 `discoverCatalog()`、原站推荐与分类入口：标准分类继续作用于当前数据，原站分类调用真实分类接口。空标签不会被说成该源没有该题材；计数 0 明确只代表当前已加载结果，筛选空时说明标签未映射数量。
- 按 Venera 实际协议支持 singlePageWithMultiPart、multiPartPage、multiPageComicList、mixed、loadNext、ranking.loadWithNext、静态/动态分类与 optionLoader。账号提示卡不进入推荐。
- mixed 文档写 0-based，但 Venera 当前 MultiPageLoadingState 从 1 开始，nhentai 配置也是 1；桥接以实际行为为准，显式 pageBase:0 可兼容文档写法。
- 嗶哩接入 Keiyoushi 公开 `/top/lastupdate/` 与 `/top/weekvisit/`；扑飞复用已验证热门目录并保存供应商链接；vomic 保留原始 updated_at，不把全首页写成今日更新。原有禁用/付费/自托管源政策保持现有仓库规则。
- 不同源有不同能力；推荐协议接入并不等于登录、站点防护或网络实时可用。缺失热议、点击、特定时间范围仍明确说明，并提供原站入口。没有把热门当作点击，也没有把原站推荐混入四维统计聚合。
