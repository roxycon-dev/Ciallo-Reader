# Ciallo阅读｜A+C 视觉设计规范（审阅稿）

## 方向

**晶透阅读 × 聚焦产品。** 让当前版本的真实 App 界面作为主角，影片灯光和设备空间提供高级感。画面由近黑起，进入浅色阅读段，再回到深色品牌结尾。避免彩色光污染、满屏 UI 拼贴、假装原生界面的后期卡片。

## 可追溯的制作决策

| 已确认需求 / 源码依据 | 影片执行 |
|---|---|
| 用户选 A+C、强调玻璃；`GlassKit.kt` 有实时 blur、vibrancy、lens 与边缘高光 | 至少一镜拍 App 内真实玻璃卡片，镜头放慢到能辨识内容；后期玻璃只作为场景光学层。 |
| 用户说主题色/强调色可改；`Theme.kt` 确认五档主色与 600ms 切换 | 品牌片用中性黑白银，浅薄的青绿仅作为灯光，不宣称这是产品唯一配色。 |
| 用户要求实机；旧 `docs/screenshots` 被明确否定 | 所有 UI 使用当前手机录屏/截图；旧关键帧退出交付链。 |
| 用户要求漫画约占阅读画面七成 | 漫画阅读 21 秒、小说阅读 9 秒。 |
| `PageTurnContainer.kt` 有仿真 3D 卷页 | 小说段展示 App 自身动画，保持正面机位；后期不代替原生翻页。 |
| 用户要 Roxy 一整个主镜头 | 52–57 秒单独一镜，不挤入功能蒙太奇。 |
| B站/YouTube、16:9、>60 秒、双语短卡、无旁白 | 72 秒 16:9；4 组双语字卡；钢琴与少量拟音引导节奏。 |
| CTA 要 APK 与项目主页 | 结尾两个清楚的行动入口，不使用未经核实的二维码或下载统计。 |

片尾项目主页采用 `https://github.com/a1553846342-dotcom/EASYREADER`，APK 入口采用 `https://github.com/a1553846342-dotcom/EASYREADER/releases`；2026-09-24 在线核对时，发布页有 v1.1.0 最新发布。最终导出前再核对链接。

## 画面系统

- **构图**：1920×1080 安全区域四边各 96 px。主手机占画面高度 72–88%；要读文字时屏幕正对镜头，UI 占画面至少 45%。镜头斜角只用于前后过渡，不压缩信息屏。
- **色彩**：夜景基底 `#090B0F` / `#171C22`，日景基底 `#F7FAF9` / `#FFFFFF`，文字 `#F4F6F5` / `#172025`。青绿色仅做边缘反光，最终从实机主题微调，不在 App UI 上强行改色。
- **玻璃**：中性透明，边缘高光、轻度折射和暗部厚度可见；影片中的外置透镜不能遮住 App 的真实文字。重点保留 App 原生玻璃控件的清晰边界。
- **字体**：中文标题取项目内 Noto Serif SC，正文及英文取 Noto Sans SC。中文主句 76–98 px，英文 26–34 px；极简分行、字距留足，不模仿 Apple 标志或字体文件。
- **灯光**：片头从斜上方软箱划过设备边缘；日景漫射无强烈反射；漫画段轻微侧光；Roxy 暖一点但仍是中性环境。每个场景最多一个主光方向。
- **运动**：长镜头 4–8 秒，真实操作优先。摄影机旋转少于约 8°，镜头缓推少于画面宽度 10%；节奏加速靠剪切与音乐重音，避免每个镜头都漂移。
- **转场**：短黑场、遮罩擦过、真实手机运动接切；漫画分格蒙太奇只用一次。叠化用于慢段，不把所有场景统一做成闪白。
- **信息层级**：同一时刻一个主角。字幕离开屏幕后至少 0.5 秒，给真实界面独占画面的时间。

## 声音设计

- 氛围钢琴由少量长音与简单和弦构成，无人声；35–43 秒漫画控件段抽掉低频，为玻璃触感让位。
- 关键声音：开机身光扫、搜索输入、下载完成、书架归位、漫画翻动、玻璃触碰、小说卷页、Roxy 动作、结尾品牌落定。
- 关键操作只能有一组对应拟音，声音要先服务真实交互。最终混音需控制响度与手机扬声器可辨识度。

## 视觉预览状态

3 张 1920×1080 关键帧已用当前实机素材重做并保存在 `promo/styleframes/renders/`：①用户录屏中的书架暗场登场，②用户录屏中的真实玻璃设置日景特写，③访客空间实机引导截图与应用内置 Roxy 原始形象组成的品牌镜头。旧 `docs/screenshots` 已从关键帧代码中移除。书架画面含商业作品封面，现阶段仅供内部创意审阅；公开版需替换或核对授权。

## 待实机核对

- 当前手机录制能否拍到安全演示的搜索与下载完整链路；不能则镜头 03 改为本地导入，并同步改文案。
- 漫画授权/公共领域素材是否能在独立演示环境中导入并显示；不能则需要另选可授权内容。
- 当前 App 中 Roxy 的出现路径与动作时长；片尾 APK 发布页是否确实可访问。

## 制作放行点

用户看过当前实机的 3 张关键帧及 `storyboard.md` 后，确认画面方向、文案与镜头顺序，再开始完整实机采集和视频工程。此前仅做少量安全素材预检。
